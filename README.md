# Skobal

[![CI](https://github.com/YOUR_USERNAME/skobal/actions/workflows/ci.yml/badge.svg)](https://github.com/YOUR_USERNAME/skobal/actions/workflows/ci.yml)

Skobal is a personal, Git-hosted catalog of portable AI-agent skills. Skills
keep Claude Code-compatible instructions in `SKILL.md`, while profiles choose
useful sets for a machine or context and adapters install those sets into
supported coding tools.

## Architecture

```text
                       registry.yaml
                            ^
                            | generated by skillctl
                            |
skills/* + skill.yaml ---> skillctl <--- profiles/*.yaml
                            |
                   sync / validate / test
                            |
             +--------------+---------------+
             |              |               |
          Claude          Cursor         OpenCode
       ~/.claude/      ~/.cursor/     ~/.config/opencode/
         skills          skills             skills
```

`SKILL.md` remains tool-portable. Its frontmatter contains only `name` and a
trigger-oriented `description`. Skobal-specific version, tags, targets, and
dependencies live beside it in `skill.yaml`.

## Quickstart

Requirements are Python 3.9+ and PyYAML:

```bash
python3 -m pip install PyYAML
./skillctl list
./skillctl validate
./skillctl sync --profile personal --dry-run
./skillctl sync --profile personal
```

Sync uses symlinks by default, so edits in this checkout are immediately visible
to the target tool. Pass `--copy` for self-contained copies, `--target cursor`
to restrict a profile sync, and `--prune` to remove obsolete Skobal-managed
installs. Prune never removes unmarked content.

## Add a skill

Create a lower-case, hyphenated skill name from the tested template:

```bash
./skillctl new review-release
```

Then:

1. Replace the generated `SKILL.md` workflow and trigger description.
2. Edit `skill.yaml` to set version, tags, targets, and required skills.
3. Add deterministic helpers under `scripts/` and pytest coverage under `tests/`.
4. Add the skill name to the appropriate profile files.
5. Regenerate and verify the index:

   ```bash
   ./skillctl registry
   ./skillctl validate review-release
   ./skillctl test review-release
   ```

The registry is generated from skill frontmatter and metadata. Do not edit it
by hand.

## Profiles

Profiles are named skill sets for a context. `personal` installs both example
skills into Claude, `work` targets Claude and Cursor, and `server` targets
OpenCode. Their compact format is:

```yaml
name: personal
targets: [claude]
skills: [documentation, hello-world]
```

Use `./skillctl sync --profile <name>`. A target passed with `--target` must be
enabled in that profile.

## Adapters and safe destinations

Adapters install each complete skill directory:

| Target | Default destination | Test/automation override |
| --- | --- | --- |
| Claude | `~/.claude/skills` | `SKOBAL_CLAUDE_DIR` |
| Cursor | `~/.cursor/skills` | `SKOBAL_CURSOR_DIR` |
| OpenCode | `~/.config/opencode/skills` | `SKOBAL_OPENCODE_DIR` |

Every successful install has a sidecar record under
`<destination>/.skobal-managed/`. Updates refuse to replace an unmarked path,
and prune considers only valid marker records. Tests always set all three
destination overrides to temporary directories.

Run `./skillctl doctor` to check Python, PyYAML, destination writability, and
dangling symlinks without creating destination directories.

## Development

Install test tools and run the same checks used in CI:

```bash
python3 -m pip install PyYAML pytest ruff
ruff check skillctl adapters tests skills/hello-world/scripts skills/hello-world/tests
./skillctl validate
python3 -m pytest tests/ -q
./skillctl test
```
