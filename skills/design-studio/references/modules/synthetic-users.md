# Synthetic usability testing

Start from a concrete version of a flow, storyboard, prototype, or implementation. Use the requested number of independent agents, defaulting to ten, one per profile. Use the contributor model for testers unless the brief specifies another. Testers can run in waves. Keep them independent from the designers and from one another.

1. Derive profiles from the audience and vary factors that change the task, such as prior product knowledge, task frequency, input method, connection quality, or returning after an interruption. Give each tester a distinct combination and a plausible goal. Mark inferred profile characteristics as assumptions.
2. Give each tester the same version and an outcome-based task, starting state, and relevant profile. Withhold the intended path, peer feedback, and the designers' rationale. Schedule shared UI sessions separately or use isolated state so one tester's actions cannot advance another's task.
3. Have each tester use the artifact available. Record the first action, the step and cue that influenced each difficulty, the expected outcome, whether the goal was reached, and any opinion about the experience. Mark an imagined consequence as a hypothesis. Identify a storyboard walkthrough as such, and reserve claims about live interactions or assistive technology for checks actually performed.
4. Send each round of findings to the Design Director. Group them by affected task and consequence, with the profile, observed action, and artifact version attached. Preserve conflicting reactions and severe single-profile blockers.
5. The director reviews the feedback personally by default. To delegate the decision, fork the director's current context into an Astra reviewer where supported, or hand the reviewer the brief, success criteria, tested artifact, constraints, prior decisions and their rationale, and the testers' observations. Refresh this context if the design changes between rounds. Give the reviewer authority to decide within the agreed scope and return its decisions to the director's shared record. The director resolves changes to the overall direction.
6. Judge each pain point against the user's goal. Identify what the person was trying to accomplish and where the flow broke down. A suggested fix is one option to evaluate. The director or reviewer can assign a change to one or more department managers, request a focused follow-up test, or keep the current design and record why. For a change, give managers the evidence and an observable acceptance condition. A findings-only brief ends with the assessment.
7. After a revision, testers retry the affected task on the new version and send the result back to the director or delegated reviewer. Keep the issue open if the acceptance condition still fails. At delivery the director reports which conditions were met, which findings were deferred and why, and any unresolved blockers.

Deliver a concise account of who tested what, the obstacles found, and what changed. Label the panel as synthetic. Counts describe this panel only. Customer prevalence, conversion, and preference estimates require evidence from actual users.
