# Legacy parity

Run before departments explore a migration, then revisit at integration. Inspect the old product's actual user entry points, commands, and reachable outcomes alongside the replacement. Use source, runnable screens, or supplied documentation and identify which evidence supports each claim.

Build a compact map of legacy user job, old entry point, proposed route, and verification result. Include infrequent actions and existing-user data where they affect completion. Track missing evidence as unknown. Share gaps with IA and UX early enough to shape the navigation.

Preserve the outcome even when the replacement uses a different interaction. Record the rationale for any intentional behavior change. Track new opportunities separately so the team can tell whether each original job still works. On delivery, walk the replacement path for each in-scope job and label design coverage and implementation checks according to the evidence available.
